Topic 01 · Linear Structures

Arrays & Strings 📦

The most fundamental structure in programming — a row of boxes in memory, each with an index. Master arrays and you've mastered half of LeetCode.

🚀
Want the full journey? This page is a taste. The dedicated Arrays — Zero to Master course animates all 7 patterns — prefix sum, two pointers, sliding window, Kadane, hashing, binary search, matrix — plus a 42-problem basic→hard practice sheet.

🌍 What is an Array?

Real-Life Analogy

A row of lockers in a school corridor. Every locker has a number (index) and holds one item (value). Want locker #4? You walk straight to it — no need to open lockers 0–3 first. That's why array access is O(1).

An array stores elements of the same type in contiguous memory. Because the boxes sit side by side, the computer can compute any element's address instantly: address = base + index × size.

Access O(1) Search O(n) Insert middle O(n) Delete middle O(n)
💡
Strings are arrays too — an array of characters. Every string technique (two pointers, sliding window, frequency counting) is just an array technique wearing a costume.

Topic 02 · Linear Structures

Linked Lists 🔗

Boxes that can live anywhere in memory, connected by pointers. Trade instant access for instant insertion.

🌍 What is a Linked List?

Real-Life Analogy

A treasure hunt. Each clue (node) contains a prize (data) and the location of the next clue (pointer). You can't jump to clue #4 — you must follow the chain. But inserting a new clue mid-hunt? Just rewrite one clue's "next location". Nobody else moves.

Each node holds data + a next pointer. The list is held together only by these pointers — lose the head, lose everything.

Access O(n) Search O(n) Insert at head O(1) Delete known node O(1)

The #1 interview trap: losing the rest of the list. When inserting/deleting, always rewire the new node's pointer before breaking the old link.

⚙️ Code — Reversing a List, Step by Step

The most-asked linked list question in interviews. Three pointers: prev, cur, next.

reverse_list.c 
Node *prev = NULL, *cur = head;while (cur != NULL) {    Node *next = cur->next;  // save!    cur->next = prev;        // flip    prev = cur;              // advance    cur = next;              // advance}head = prev; // new head

🧠 Quick Check

Array vs Linked List — when does the linked list win?
Right. Rewiring two pointers is O(1); an array must shift everything after the insertion point — O(n). But index access and cache locality belong to arrays.

Topic 03 · Linear Structures

Stacks & Queues 📚

Two restricted lists with opposite personalities: one serves the newest item first, the other the oldest. Restrictions are the feature, not the limitation.

🌍 Stack — Last In, First Out (LIFO)

Real-Life Analogy

A stack of plates in a canteen. New plate goes on top. Need a plate? Take from the top. The bottom plate leaves last. Your browser's Back button, Ctrl+Z, and every function call in your program work exactly like this.

🔬 Stack Lab — you drive: push & pop (max 5)
⬆ top is here
Push a few values, then pop — the glowing item is always the top. Try popping an empty stack or overfilling it.

🌍 Queue — First In, First Out (FIFO)

Real-Life Analogy

A ticket line at the cinema. You join at the rear, get served at the front. Whoever came first leaves first. Printer jobs, BFS traversal, and CPU task scheduling all run on queues.

🔬 Queue Lab — front is on the left (max 6)

⚙️ Code — Balanced Brackets with a Stack

The classic stack application: is "{[()]}" balanced? Openers get pushed; each closer must match the most recent opener — pure LIFO.

balanced.pseudo 
stack = empty()for each ch in s:    if ch is '(' '[' '{': push(ch)    else:        if stack empty or top() ≠ partner(ch): return false        pop()return stack.isEmpty()

🧠 Quick Check

You type text, then press Ctrl+Z three times. Which structure gives back your edits in the correct order?
Stack. Undo must reverse the latest action first — Last In, First Out. If undo were a queue, Ctrl+Z would revert your very first keystroke. Chaos.

Topic 04 · Non-Linear Structures

Trees 🌲

Hierarchy, not sequence. Folders inside folders, managers above employees, HTML elements inside elements — trees are everywhere data has parents and children.

🌍 What is a Binary Search Tree?

Real-Life Analogy

A family tree turned filing system: at every node, everything smaller lives left, everything bigger lives right. Looking for a value? Each comparison discards half the tree — like binary search, but as a shape.

Key vocabulary: root (top node), leaf (no children), height (longest root→leaf path). A BST adds the ordering rule: left < node < right.

Search O(log n) balanced Insert O(log n) balanced Worst (skewed) O(n)

🧪 Traversals (Live)

Three ways to visit every node — the difference is just when you visit the root relative to its subtrees. Run all three on the same BST and compare the outputs.

🔬 Traversal Lab — one BST, three orders
Pick a traversal — nodes light up in visit order. Notice inorder gives 20→30→40→50→60→70→80: sorted!
🎯
Interview shortcut: "print BST in sorted order" = inorder. "Copy a tree" = preorder. "Delete a tree" = postorder (children before parent). Level-by-level = BFS with a queue.

⚙️ Code — Inorder is 3 Lines of Recursion

inorder.c 
void inorder(Node *root) {    if (root == NULL) return;    inorder(root->left);    printf("%d ", root->data);    inorder(root->right);}
💡
Wait — 6 lines, 4 notes? Lines 3–5 are the heart: Left, Root, Right. Swap that order and you get preorder (Root, Left, Right) or postorder (Left, Right, Root). One function, three traversals.

🧠 Quick Check

You run inorder traversal on a BST and the output is NOT sorted. What do you know for certain?
Correct — and that's LeetCode 98 (Validate BST) solved. Inorder on a true BST is always sorted; a violation anywhere breaks the sequence. Unbalanced trees still sort fine.

Topic 05 · Non-Linear Structures

Hashing 🔢

The structure that turns "search the whole array" into "jump straight to the answer". Average O(1) lookup — the closest thing DSA has to magic.

🌍 What is a Hash Table?

Real-Life Analogy

A library with a formula instead of a librarian. Instead of scanning every shelf for a book, you compute shelf = hash(title) and walk directly there. Two books can map to the same shelf — that's a collision, and the shelf just holds both (chaining).

A hash function converts a key into a bucket index — commonly key % table_size. Good hash functions spread keys evenly; a terrible one puts everything in one bucket and degrades lookup to O(n).

Insert O(1) avg Lookup O(1) avg Delete O(1) avg Worst case O(n)

⚙️ Code — Two Sum, the Hash Way

Remember Two Sum from Topic 01? Two pointers needed a sorted array. A HashMap solves the unsorted version in one pass.

two_sum.pseudo 
seen = HashMap()for i in 0..n-1:    need = target − arr[i]    if need in seen:        return (seen[need], i)    seen[arr[i]] = ireturn not_found
🎯
The hashing reflex: whenever a problem says "have I seen this before?", "count frequencies", or "find duplicates" — your brain should shout HashMap. It trades O(n) space for O(1) time.

🧠 Quick Check

You insert 1,000,001 keys into a table with 1,000,000 buckets. What is guaranteed?
Pigeonhole: more pigeons than holes → some hole has two pigeons. Collisions are inevitable at scale; good tables handle them (chaining / open addressing) and stay O(1) on average.

Topic 06 · Non-Linear Structures

Graphs 🕸️

Nodes + connections, no rules about shape. Google Maps, friend networks, flight routes, the internet itself — all graphs. The final boss of data structures.

🚀
Want the full journey? This page is a taste. The dedicated Graphs — Zero to Master course animates BFS, DFS, islands, topological sort and Dijkstra node by node — plus the Ripple Lab and a 36-problem basic→hard sheet.

🌍 What is a Graph?

Real-Life Analogy

Your city's metro map. Stations are vertices, tracks are edges. Some routes are one-way (directed), some tracks are longer (weighted). "How do I get from A to F with fewest stops?" — that's literally BFS.

A tree is just a graph with no cycles and one root. Remove those restrictions and you get graphs: cycles allowed, multiple paths allowed, even disconnected islands allowed. Stored as an adjacency list (each node's neighbors) or adjacency matrix (n×n grid).

🧪 BFS vs DFS — Race Them (Live)

Same graph, same start (A). BFS explores in rings — closest first, using a queue. DFS dives down one path until stuck, using a stack. Run both and compare visit orders.

🔬 Traversal Lab — edges: A–B, A–C, B–D, C–E, D–F, E–F
BFS goes A → B → C (neighbors first). DFS goes A → B → D → F (deep first). Same nodes, different philosophy.
💡
Which one when? Shortest path (unweighted) → BFS. Explore everything / detect cycles / topological sort → DFS. Weighted shortest path → Dijkstra (BFS + priority queue).

⚙️ Code — BFS Skeleton (memorize this shape)

bfs.pseudo 
queue = [start]visited = {start}while queue not empty:    node = queue.dequeue()    for each nbr in adj[node]:        if nbr not in visited: visited.add(nbr); queue.enqueue(nbr)# every reachable node visited exactly once → O(V + E)

🧠 Quick Check

Find the minimum number of moves for a knight to reach a chessboard square. BFS or DFS?
BFS. Board squares = vertices, knight moves = edges, every move costs 1. BFS reaches each square via the fewest possible moves. DFS finds a path — often a wildly long one.

Topic 08 · Algorithms

Dynamic Programming 🧠

The scariest name for the simplest idea: never solve the same subproblem twice. Solve small, remember the answer, build up.

🚀
Want the full journey? This page is a taste. The dedicated DP — Zero to Master course takes you zero → master: the DP Lab, 10 step-by-step animations (recursion trees, knapsack tables, LCS grids), 18 Python solutions, interview Q&A and a 42-problem practice sheet.

🌍 The Core Idea

Real-Life Analogy

Someone asks "what's 48 × 17?" — you calculate: 816. They ask again. Do you recalculate? No — you remember. That's memoization. DP is just recursion with a memory, or a table filled bottom-up.

A problem is a DP problem when it has both:

  • Overlapping subproblems — the same smaller question gets asked repeatedly (fib(3) inside fib(5) inside fib(6)…)
  • Optimal substructure — the best answer for size n is built from best answers of smaller sizes

⚙️ Code — The 4-Step DP Recipe

Every DP solution follows the same recipe. Here it is on Climbing Stairs (LeetCode 70): you can climb 1 or 2 steps — how many ways to reach step n?

climbing_stairs.pseudo 
# dp[i] = ways to reach step idp[0] = 1; dp[1] = 1for i in 2..n:    dp[i] = dp[i-1] + dp[i-2]return dp[n]
🎯
The recipe never changes: ① define what dp[i] means in plain English → ② set base cases → ③ write the transition (how big answers use small ones) → ④ read off the answer. If you can fill those 4 blanks, you can solve any DP.

🧠 Quick Check

Naive recursive fib(50) takes minutes. The DP version takes microseconds. What exactly did DP eliminate?
Recomputation. Naive fib(50) recomputes fib(2) about 4.8 billion times. DP (memoized recursion or a table — both count!) computes it once. O(2ⁿ) → O(n), by remembering.
