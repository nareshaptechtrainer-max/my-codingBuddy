Level 1 — What an Array Really Is

One block of memory + one multiplication = instant access

Boxes in a row, glued together

An array is a contiguous block of memory — every element same size, side by side

  • Contiguous: element i+1 physically sits right after element i. No gaps, no jumping around memory.
  • That's why access is O(1): Python never "walks" to index 5 — it CALCULATES where it is: address = base + i × size. One multiplication, one jump. Try it in the lab →
  • Python's list is a dynamic array: same idea, but it automatically grows (roughly doubling) when full. That's why append is O(1) amortized.
  • Negative indices are sugar: arr[-1] just means arr[len(arr) - 1].
📏
Interview line"Array indexing is O(1) because the address is computed arithmetically — base address plus index times element size — not searched for."

🧪 Address Lab — why arr[i] is instant

address = 1000 + 3 × 4 = 1012 → jump straight there → value 3. No walking!

Pattern 1 — Prefix Sum

Pre-compute running totals once → answer every range-sum question in O(1)

Pay once, query forever

prefix[i] = sum of everything up to index i. Then sum(l..r) = prefix[r] − prefix[l−1]

  • Spot it when: "sum of subarray", "range sum queries", "equilibrium/pivot index", "subarray with sum K".
  • Without it: each range-sum question costs O(n). With 10⁵ queries → 10¹⁰ operations → TLE.
  • With it: O(n) once to build, then every query is a single subtraction.
  • Same trick works for prefix max, prefix product, prefix XOR — anything cumulative.
the pattern in code 
arr = [2, 4, 1, 3, 5]

prefix = [0] * len(arr)
prefix[0] = arr[0]
for i in range(1, len(arr)):
    prefix[i] = prefix[i-1] + arr[i]
# prefix = [2, 6, 7, 10, 15]

def range_sum(l, r):          # inclusive
    if l == 0:
        return prefix[r]
    return prefix[r] - prefix[l-1]

range_sum(1, 3)   # 4+1+3 = 8, in O(1)!

Pattern 2 — Two Pointers

Start at both ends, squeeze inward — one decision per step kills the O(n²)

Squeeze from both ends

Works when the array is SORTED (or when moving a pointer has a predictable effect)

  • Spot it when: "sorted array + find a pair/triplet", "container/area between lines", "remove duplicates in place", "is it a palindrome".
  • The magic: sum too BIG? Only moving right left can shrink it. Too SMALL? Only moving left right can grow it. Every step safely discards one element → O(n).
  • Second flavor — slow/fast pointers moving the same direction: overwrite-in-place problems (move zeroes, remove duplicates).
pair with target sum — sorted array 
def pair_sum(arr, target):     # arr is sorted
    left, right = 0, len(arr) - 1
    while left < right:
        s = arr[left] + arr[right]
        if s == target:
            return (left, right)
        if s < target:
            left += 1      # need bigger sum
        else:
            right -= 1     # need smaller sum
    return None            # no pair exists
slow/fast flavor — move zeroes (LC 283) 
def move_zeroes(arr):
    slow = 0                    # next non-zero slot
    for fast in range(len(arr)):
        if arr[fast] != 0:
            arr[slow], arr[fast] = arr[fast], arr[slow]
            slow += 1
# [0,1,0,3,12] → [1,3,12,0,0] in ONE pass

Pattern 3 — Sliding Window

Don't recompute the window — subtract what leaves, add what enters

Recycle the overlap

Two windows next to each other share almost everything — only the edges differ

  • Spot it when: "subarray of size k", "longest/shortest subarray satisfying a condition", "max sum window", any CONTIGUOUS chunk question.
  • Fixed window (size k): compute window 1 fully; then slide: sum += arr[right] − arr[left]. Each slide is O(1) instead of O(k).
  • Variable window: grow right while the condition allows; when broken, shrink from left until it's fixed. Both pointers only move forward → O(n) total.
  • Sliding window IS two pointers moving the same direction — with a running "state" (sum/count/set) carried between moves.
fixed window — max sum of size k 
def max_window(arr, k):
    wsum = sum(arr[:k])        # first window
    best = wsum
    for right in range(k, len(arr)):
        wsum += arr[right] - arr[right - k]
        best = max(best, wsum)
    return best
variable window — smallest subarray ≥ target (LC 209) 
def min_subarray(arr, target):
    left = wsum = 0
    best = float('inf')
    for right in range(len(arr)):
        wsum += arr[right]           # grow
        while wsum >= target:        # shrink
            best = min(best, right - left + 1)
            wsum -= arr[left]
            left += 1
    return 0 if best == float('inf') else best

Pattern 4 — Kadane's Algorithm

Maximum subarray sum in one pass — the most-asked array question ever

At every step: extend or restart

Walking left to right, ask ONE question: "does the past help me, or is it dead weight?"

  • Spot it when: "maximum/minimum subarray sum", "best contiguous run", "max product subarray" (with a twist).
  • best_here = max(x, best_here + x) — if the running sum went negative, carrying it only hurts → restart fresh at x.
  • Track the best best_here ever seen — that's the answer. O(n) time, O(1) space.
  • This is actually 1-D dynamic programming — the full story is on the DP page.
Kadane in 7 lines (LC 53) 
def max_subarray(arr):
    best_here = best = arr[0]
    for x in arr[1:]:
        # extend the run, or restart at x?
        best_here = max(x, best_here + x)
        best = max(best, best_here)
    return best

max_subarray([-2, 3, -1, 4, -5])   # 6 → [3,-1,4]

Pattern 5 — Hashing (dict & set)

Trade a little memory for instant "have I seen this?" answers

Remember, don't re-scan

Any time your inner loop only asks "does X exist?" or "how many X?" — a dict/set answers in O(1)

  • Spot it when: "two sum (unsorted)", "contains duplicate", "frequency / majority element", "intersection of arrays", "longest consecutive sequence".
  • The rewrite recipe: inner loop searching → set/dict lookup. O(n²) → O(n) instantly.
  • Cost: O(n) extra memory. Interviewers expect you to SAY this trade-off out loud.
  • On the Python page you saw HOW dicts jump in O(1) — here's where it wins battles.
Two Sum, unsorted — THE interview classic (LC 1) 
def two_sum(arr, target):
    seen = {}                  # value → index
    for i, x in enumerate(arr):
        need = target - x
        if need in seen:       # O(1) lookup!
            return (seen[need], i)
        seen[x] = i
    return None
longest consecutive sequence (LC 128) 
def longest_streak(arr):
    s, best = set(arr), 0
    for x in s:
        if x - 1 not in s:       # only start
            y = x                # at streak heads
            while y + 1 in s:
                y += 1
            best = max(best, y - x + 1)
    return best     # O(n) — each number visited twice max

Pattern 6 — Sorting & Binary Search

Sorted data is a superpower: discard HALF the array with every question

Ask the middle, throw half away

1,000,000,000 elements → found in ~30 comparisons. That's log₂(n)

  • Spot it when: the array is SORTED (or rotated-sorted), or you can ask a yes/no question whose answers form a monotonic ✗✗✗✓✓✓ pattern ("binary search on answer").
  • Compare with the middle: too small → answer lives in the right half; too big → left half. Either way, HALF the field dies.
  • Sorting first costs O(n log n) — worth it if you'll search many times, or if sorted order unlocks two-pointers.
  • The bug factory: use while lo <= hi, and mid = (lo + hi) // 2; move lo = mid + 1 / hi = mid − 1. Off-by-ones cause infinite loops!
binary search — memorize this exact shape 
def binary_search(arr, target):   # sorted!
    lo, hi = 0, len(arr) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if arr[mid] == target:
            return mid
        if arr[mid] < target:
            lo = mid + 1     # go right
        else:
            hi = mid - 1     # go left
    return -1
🐍
Python sorting factsarr.sort() = in-place, returns None. sorted(arr) = new list. Both are Timsort, O(n log n), STABLE (equal items keep their order). Sort by anything: arr.sort(key=lambda p: p[1], reverse=True).

Pattern 7 — 2D Arrays (Matrix)

Rows of rows — plus the three walks every interview loves

A matrix is a list of lists

m[row][col] — row first, then column. Master the traversals and the rest follows

create · read · walk 
m = [[1, 2, 3],
     [4, 5, 6],
     [7, 8, 9]]
m[1][2]          # 6 — row 1, col 2

for row in m:                 # row by row
    for x in row:
        print(x, end=" ")

# build n×n of zeros — the RIGHT way
grid = [[0] * 3 for _ in range(3)]
# ❌ [[0]*3]*3 → THREE LABELS ON ONE ROW!
#    changing grid[0][0] changes every row
rotate 90° clockwise (LC 48) — the elegant way 
# step 1: transpose (flip across diagonal)
for i in range(n):
    for j in range(i + 1, n):
        m[i][j], m[j][i] = m[j][i], m[i][j]
# step 2: reverse each row
for row in m:
    row.reverse()
# transpose + mirror = rotation. Two clean loops,
# in place, no second matrix.
⚠️
The aliased-rows trap[[0]*n]*n repeats the SAME inner list n times (remember aliasing from the Python page?). Every row changes together. Always use the comprehension form.

✅ How to attack ANY array problem

  • 1. Say the brute force out loud FIRST ("check every pair, O(n²)") — it's your safety net
  • 2. Find the repeated work the brute force does — that's what a pattern removes
  • 3. Match a trigger phrase to the map above
  • 4. Walk a 5-element example BY HAND before coding
  • 5. Test edge cases: empty array, single element, all same, all negative
  • 6. State time AND space complexity without being asked

❌ The 5 classic array mistakes

  • Off-by-one: range(len(arr)) vs range(len(arr)-1) — walk your loop bounds on paper
  • Modifying the list you're iterating — items get skipped silently
  • [[0]*n]*n aliased matrix rows (one row, n labels)
  • Forgetting Kadane/two-pointer arrays can be ALL negative — initialize with arr[0], not 0
  • Binary search with while lo < hi + wrong mid updates → infinite loop

💬 Rapid-fire Interview Q&A

Q1Why is array access O(1) but search O(n)?+
Access computes the address directly: base + index × element-size — one multiplication regardless of size. Search has no such formula for VALUES: an unsorted array gives no clue where a value hides, so every cell must be checked. Sorting restores structure, enabling O(log n) binary search.
Q2Array vs linked list — when does each win?+
Array wins at random access O(1) and cache-friendliness (contiguous memory). Linked list wins at insert/delete at a KNOWN position O(1) — no shifting. Array insert/delete is O(n); linked list access is O(n). Rule: read-heavy → array, splice-heavy → linked list.
Q3How does Python's list grow? Why is append "amortized" O(1)?+
Python over-allocates: when the block fills, it allocates a bigger block (~1.125×) and copies everything — that ONE append is O(n). But it buys many cheap O(1) appends before the next resize, so the average per append stays O(1). That average-over-a-sequence cost is called amortized.
Q4Two pointers vs sliding window — what's the actual difference?+
Two pointers usually start at OPPOSITE ends of sorted data and squeeze inward, discarding one element per comparison. Sliding window moves both pointers FORWARD over unsorted data, maintaining running state (sum, counts, a set) about the current contiguous chunk. Window = "contiguous subarray" questions; opposite-end pointers = "pair/triplet in sorted" questions.
Q5When can I binary search something that isn't a sorted array?+
Whenever you can define a yes/no check that's monotonic — answers look like ✗✗✗✗✓✓✓. Example: "min ship capacity to deliver in D days" (LC 1011) — if capacity C works, every capacity above C works too. Binary search the smallest ✓. This "binary search on the answer" solves many hard problems.
Q6What does "in-place" mean and why do interviewers demand it?+
O(1) extra space — mutate the given array instead of building a copy. It proves you can manage indices carefully (slow/fast pointers, swaps). Examples: move zeroes, rotate image, Dutch flag. Trade-off to mention: in-place often sacrifices readability and destroys the input.
Q7Kadane's returned the wrong answer for all-negative arrays. Why?+
Because it was initialized with 0 instead of arr[0]. With best = 0, an all-negative array returns 0 — the sum of an EMPTY subarray, usually not allowed. Initialize both best and best_here to arr[0] and start the loop from index 1. This exact bug is a favorite interviewer probe.
Q8Why is Python's sort "stable" and when does it matter?+
Stable = equal elements keep their original relative order. Timsort guarantees it. It matters for multi-key sorting: sort by name first, then by grade — students with equal grades stay alphabetical. You get multi-level sorting just by sorting twice in reverse priority order.
