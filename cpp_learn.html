Level 1 — Getting Started

What C++ is, how compilation works, and the anatomy of your first program

Why C++?

C's raw speed + objects + a giant standard library

  • Blazing fast: compiled straight to machine code. Game engines (Unreal), browsers (Chrome), trading systems — all C++.
  • Competitive programming's #1 language: the STL gives you sorted maps, heaps and sorts in one line, at C speed.
  • You manage memory: pointers, stack vs heap — you learn what other languages hide. That knowledge transfers everywhere.
  • For placements: most Indian service + product companies accept C++ everywhere Java/Python are accepted.
⚙️
Compiled vs interpreted — the interview line"C++ translates the WHOLE program to machine code once, before running (compile time). Python translates line by line while running. That's why C++ catches type errors before the program ever starts — and why it's 10-100× faster."

Level 1 — Variables & Static Typing

Every variable declares its type ONCE and keeps it forever — the compiler is watching

The type is a contract

In Python a name can point anywhere. In C++ a variable IS a typed box of fixed size — forever.

  • int age = 20; reserves exactly 4 bytes shaped like an int. Assign a string to it later? The COMPILER refuses — the program never even builds.
  • That's static typing: whole categories of bugs die at compile time instead of exploding at 2 AM in production.
  • Naming rules are the same as everywhere: letters/digits/underscore, no leading digit, case-sensitive. Convention: camelCase or snake_case — pick one and stay consistent.
  • const double PI = 3.14159; — a variable that can never change. Use it for every fixed value.

Level 3 — Pointers

The topic that scares everyone — until you SEE it. A pointer is just a variable holding an address.

A pointer stores an address

Two operators, two meanings: & = "address of", * = "value at"

  • int* p = &age; — p holds WHERE age lives, not its value.
  • *p (dereference) follows the address → gives you age itself. *p = 21 changes age remotely!
  • References (int& r = age;) are friendlier pointers: no * needed, can't be null, can't be reseated. Prefer them; know both.
  • Heap memory: new int[1000] allocates at runtime → YOU must delete[] it, or the memory leaks. (Modern C++: use vectors/smart pointers instead.)

Level 4 — Object-Oriented C++

Classes, constructors, inheritance and the star of every interview: virtual functions

🎬 Animation — constructor builds the object

access specifiers — the encapsulation tools 
class BankAccount {
private:                  // hidden from outside
    double balance = 0;
public:                   // the official doorway
    void deposit(double amt) {
        if (amt > 0) balance += amt;
    }
    double getBalance() { return balance; }
};
// acc.balance = -999;   ❌ compiler blocks it!

Inheritance + virtual = runtime polymorphism

the interview classic 
class Animal {
public:
    virtual string speak() {   // virtual!
        return "...";
    }
};
class Dog : public Animal {
public:
    string speak() override { return "Woof!"; }
};
class Cat : public Animal {
public:
    string speak() override { return "Meow!"; }
};

Animal* pets[] = { new Dog(), new Cat() };
for (Animal* p : pets)
    cout << p->speak();   // Woof! Meow!
// WITHOUT virtual: "..." "..." — base version!
🧠
Why virtual mattersWithout virtual, the call is bound at COMPILE time to the pointer's type (Animal). With it, C++ checks the REAL object at RUNTIME via the vtable. "What is a vtable?" is a guaranteed C++ interview question — answer: a hidden table of function pointers, one per class.

The Master Map

C++ habits that mark you as senior + rapid-fire interview Q&A

✅ Signs of a C++ master

  • vector and string by default — raw arrays/char* only with a reason
  • Big objects passed as const T& — never by copy
  • long long the moment sums can exceed 2×10⁹
  • Uses auto, range-for, and STL algorithms before hand-rolled loops
  • Can explain stack vs heap, and why new without delete leaks
  • Says "vtable" when asked how virtual functions work

❌ The 6 classic C++ mistakes

  • int overflow: 10⁵ × 10⁵ = 10¹⁰ doesn't fit → garbage
  • 7 / 2 == 3 — integer division chops silently
  • arr[n] out of bounds — no error, just corrupted memory
  • Missing break in switch → fall-through chaos
  • if (x = 5) — assignment where you meant ==
  • Forgetting virtual → base method called on child objects

💬 Rapid-fire Interview Q&A

Q1Difference between C and C++?+
C is procedural; C++ adds OOP (classes, inheritance, polymorphism), function/operator overloading, references, templates and the STL, plus stricter type checking. C++ is (nearly) a superset — most C programs compile as C++.
Q2Stack vs heap memory?+
Stack: automatic, fast, small — local variables live here and die when their scope ends. Heap: manual (new/delete), large, survives across scopes — YOU own the lifetime. Forgetting delete = memory leak; deleting twice = crash. Vectors/smart pointers manage heap memory for you (RAII).
Q3Pointer vs reference?+
A pointer is a variable holding an address: can be null, can be reseated, needs * to use. A reference is a permanent alias: never null, bound once, used like the original variable. Rule: references for function parameters, pointers when "nothing" is a valid state or you must re-point.
Q4What happens if you don't write virtual?+
Calls through a base pointer bind at compile time to the BASE version — child overrides are ignored. virtual switches to runtime dispatch through the vtable, so the real object's version runs. Also: always make base-class destructors virtual, or deleting through a base pointer skips the child's destructor.
Q5map vs unordered_map — when each?+
unordered_map = hash table: O(1) average, no order — default for counting/lookup. map = red-black tree: O(log n) but keys stay SORTED, giving lower_bound/upper_bound range queries — priceless for "smallest key ≥ x" problems. Same choice applies to set vs unordered_set.
Q6++i vs i++ — does it matter?+
For ints in a loop: no difference after optimization. For iterators/objects, i++ must create a COPY of the old value to return; ++i doesn't. Habit: write ++i in C++ loops — costs nothing, occasionally faster, and interviewers notice.
Q7What is RAII?+
Resource Acquisition Is Initialization: tie a resource (memory, file, lock) to an object's lifetime — the constructor takes it, the destructor releases it AUTOMATICALLY, even during exceptions. vector, string, unique_ptr, lock_guard are all RAII. It's C++'s answer to garbage collection.
Q8Function overloading vs overriding?+
Overloading: SAME scope, same name, different parameter lists — resolved at compile time. Overriding: child class redefines a parent's virtual function with the SAME signature — resolved at runtime. Overloading is compile-time polymorphism; overriding is runtime polymorphism.
