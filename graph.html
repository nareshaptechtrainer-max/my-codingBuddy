Level 1 — What is a Graph?

Dots and lines — the most flexible data structure in computer science

Dots + lines = everything

A graph is just a set of vertices (nodes) connected by edges. That's the whole definition.

  • Vertex (node): a thing — a person, a city, a webpage, a course.
  • Edge: a relationship — friendship, road, hyperlink, prerequisite.
  • Degree: how many edges touch a vertex.
  • Path: a sequence of edges from one vertex to another. Cycle: a path that returns to its start.
  • A tree is just a graph with no cycles and exactly n−1 edges — trees are baby graphs!
🌍
Spot the graph in the wildGoogle Maps (cities + roads, weighted) · Instagram (users + follows, directed) · WhatsApp groups (users + shared groups) · Course prerequisites (courses + "must do first", directed acyclic) · Your brain (neurons + synapses).

Pattern 1 — Breadth-First Search (BFS)

The ripple, formalized: a queue + a visited set

Level by level, with a queue

Visit me → queue my neighbors → serve the queue in arrival order. First-come, first-served = levels.

  • Spot it when: "shortest path" in an UNWEIGHTED graph, "minimum number of steps/moves", "nearest…", "spread/infection time", level-order anything.
  • The queue guarantees you finish distance-1 nodes before touching distance-2 nodes — that's why BFS finds shortest paths.
  • The visited set stops infinite loops on cycles. Mark visited WHEN YOU ENQUEUE, not when you pop — or nodes enter the queue twice.
  • Complexity: O(V + E) — each vertex enqueued once, each edge looked at once (twice if undirected).
the BFS template — memorize it EXACTLY 
from collections import deque

def bfs(graph, start):
    visited = {start}
    q = deque([start])
    while q:
        node = q.popleft()        # FIFO!
        print(node)               # "process"
        for nb in graph[node]:
            if nb not in visited:
                visited.add(nb)   # mark HERE
                q.append(nb)
shortest distance version (track levels) 
def bfs_dist(graph, start):
    dist = {start: 0}
    q = deque([start])
    while q:
        node = q.popleft()
        for nb in graph[node]:
            if nb not in dist:
                dist[nb] = dist[node] + 1
                q.append(nb)
    return dist    # fewest edges to every node

Pattern 2 — Depth-First Search (DFS)

Go deep first, backtrack when stuck — recursion's favorite algorithm

Dive deep, then backtrack

Like exploring a maze: keep walking until a dead end, then walk back to the last junction

  • Spot it when: "count islands/components", "does a cycle exist", "explore ALL paths", "flood fill", backtracking puzzles.
  • DFS = BFS with a stack instead of a queue — or simply recursion (the call stack IS your stack).
  • DFS does NOT find shortest paths — it commits to one direction and may find a long route first. Use BFS for "shortest".
  • Same complexity as BFS: O(V + E). Recursion depth can hit V — for huge graphs use the iterative version.
recursive DFS — 5 lines 
def dfs(graph, node, visited=None):
    if visited is None:
        visited = set()
    visited.add(node)
    print(node)                  # "process"
    for nb in graph[node]:
        if nb not in visited:
            dfs(graph, nb, visited)
    return visited
counting connected components — DFS's #1 job 
def count_components(graph, nodes):
    visited, count = set(), 0
    for n in nodes:
        if n not in visited:
            count += 1           # new island!
            dfs(graph, n, visited)
    return count

Pattern 3 — The Grid IS a Graph

Number of Islands: the most-asked graph question, animated cell by cell

Every cell is a node, every side is an edge

No one hands you a graph in interviews — they hand you a GRID and expect you to see the graph

  • A cell's neighbors are up/down/left/right: (r±1, c) and (r, c±1). That's the adjacency list — computed on the fly.
  • Number of Islands (LC 200): scan every cell; when you hit unvisited LAND, that's a NEW island → flood-fill (DFS) to mark the whole island visited.
  • Flood fill = the paint-bucket tool in MS Paint. Same algorithm, literally.
  • Complexity O(rows × cols): every cell visited a constant number of times.
Number of Islands — the full solution 
def num_islands(grid):
    R, C = len(grid), len(grid[0])
    def sink(r, c):              # DFS flood fill
        if not (0 <= r < R and 0 <= c < C):
            return               # off the map
        if grid[r][c] != "1":
            return               # water / visited
        grid[r][c] = "V"         # mark visited
        sink(r+1, c); sink(r-1, c)
        sink(r, c+1); sink(r, c-1)

    count = 0
    for r in range(R):
        for c in range(C):
            if grid[r][c] == "1":
                count += 1       # new island!
                sink(r, c)
    return count

Pattern 4 — Topological Sort

"What order do I take my courses?" — dependency ordering for DAGs

Do prerequisites first

A valid order where every arrow points forward. Only possible if there's no cycle!

  • Spot it when: "prerequisites", "build order", "task scheduling", "can you finish all courses?"
  • Kahn's algorithm (BFS): repeatedly take a node with indegree 0 (no pending prerequisites), remove it, and decrease its neighbors' indegrees. New zeros join the queue.
  • If you process FEWER than V nodes → a cycle exists → no valid order (deadlock!). Cycle detection for free.
  • Only works on DAGs (directed acyclic graphs) — a cycle means "A needs B needs A": impossible.
Kahn's algorithm (Course Schedule, LC 207/210) 
from collections import deque

def topo_order(graph, nodes):
    indeg = {n: 0 for n in nodes}
    for n in nodes:
        for nb in graph[n]:
            indeg[nb] += 1
    q = deque([n for n in nodes if indeg[n] == 0])
    order = []
    while q:
        n = q.popleft()
        order.append(n)
        for nb in graph[n]:
            indeg[nb] -= 1
            if indeg[nb] == 0:   # prereqs done!
                q.append(nb)
    return order if len(order) == len(nodes) else None
    # None → cycle → impossible to finish

Pattern 5 — Dijkstra's Algorithm

Shortest path when edges have WEIGHTS — BFS's big brother with a priority queue

Always expand the cheapest frontier

BFS pops "oldest first". Dijkstra pops "cheapest total distance first" — that single change handles weights

  • Spot it when: "shortest/cheapest path" + edges have different costs (time, price, distance). Unweighted? Plain BFS is enough — don't over-engineer!
  • Keep a dist map (best known cost to each node, start = 0, rest = ∞). A min-heap always serves the cheapest unfinished node.
  • Relaxation: for each neighbor, if dist[node] + weight < dist[nb] → found a better route → update and push.
  • ⚠️ Dijkstra breaks on NEGATIVE weights (use Bellman-Ford there). Complexity: O((V+E) log V).
Dijkstra with heapq (Network Delay, LC 743) 
import heapq

def dijkstra(graph, start):
    # graph[u] = [(v, weight), ...]
    dist = {start: 0}
    heap = [(0, start)]
    while heap:
        d, node = heapq.heappop(heap)
        if d > dist.get(node, float('inf')):
            continue           # stale entry, skip
        for nb, w in graph[node]:
            nd = d + w
            if nd < dist.get(nb, float('inf')):
                dist[nb] = nd            # relax!
                heapq.heappush(heap, (nd, nb))
    return dist

✅ The graph interview checklist

  • 1. Name the graph out loud: "nodes are ___, edges are ___"
  • 2. Directed or undirected? Weighted? Could it have cycles?
  • 3. Build the adjacency list (both directions if undirected!)
  • 4. Pick the algorithm from the trigger phrase
  • 5. Always carry a visited set — cycles bite otherwise
  • 6. State O(V + E) and the space cost unprompted

❌ The 5 classic graph mistakes

  • Forgetting the reverse edge in undirected graphs → half the graph invisible
  • Marking visited on POP instead of on ENQUEUE → nodes queued twice
  • Using DFS for "shortest path" — it finds A path, not the SHORTEST
  • Ignoring disconnected graphs — loop over ALL nodes as potential starts
  • Recursion depth overflow on huge grids → switch to iterative DFS/BFS

💬 Rapid-fire Interview Q&A

Q1Why does BFS find the shortest path but DFS doesn't?+
BFS explores in expanding rings: it visits ALL nodes at distance d before ANY node at distance d+1, so the first time it touches the target, it arrived by a minimum-edge route. DFS commits to one branch and may reach the target through a long detour before trying short routes.
Q2How do you detect a cycle in a graph?+
Undirected: during DFS, meeting a visited node that is NOT your direct parent = cycle. Directed: track the current recursion path (grey/black coloring) — meeting a node already ON the current path = cycle. Or run Kahn's topological sort: processing fewer than V nodes proves a cycle.
Q3What is Union-Find and when do you reach for it?+
A structure answering "are X and Y in the same group?" and "merge these groups" in near-O(1) (with path compression + union by rank). Perfect when edges arrive one by one and you only care about connectivity — redundant connection (LC 684), accounts merge, Kruskal's MST. No traversal needed at all.
Q4What exactly is multi-source BFS?+
Start BFS with SEVERAL nodes already in the queue at distance 0 — all rotten oranges, all ocean-border cells. The ripple spreads from all sources simultaneously, giving each cell its distance to the NEAREST source in one pass. Same template; only the initial queue changes.
Q5Why does Dijkstra fail with negative weights?+
Dijkstra finalizes a node the moment it pops from the heap, assuming no future route can beat the current best — true only if edges never decrease a path's cost. A negative edge later could produce a cheaper route to an already-finalized node. Bellman-Ford re-relaxes all edges V−1 times, so it tolerates negatives (and detects negative cycles).
Q6Grid problems: when BFS and when DFS?+
Counting/marking regions (islands, flood fill) → DFS, simplest to write. Any "minimum steps/time/distance" on a grid (rotting oranges, 01-matrix, shortest maze path) → BFS, because level = distance. If the question says "nearest" or "minimum", DFS is the wrong tool.
Q7A tree is a graph — so why do trees get separate treatment?+
A tree is a connected acyclic graph: exactly n−1 edges, exactly one path between any two nodes. No cycles → no visited set needed; one path → no shortest-path machinery. All tree traversals (preorder/inorder/postorder) are just DFS variants; level-order is BFS.
Q8How would you find the shortest path in a maze with portals/keys?+
Expand the STATE: a node isn't just a position — it's (position + keys held) or (position + portal used). BFS over this bigger state graph still works because each state transition costs 1. "BFS on states" cracks most hard maze variants (LC 864, 847).
